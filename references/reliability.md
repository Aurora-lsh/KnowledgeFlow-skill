# KnowledgeFlow 可靠性操作规则

这些记录在用户的 Notion 入口内维护，使用普通子页和简短表格即可。它们约束助手如何操作，不是独立执行程序，也不提供原子写入或分布式唯一性保证。优先沿用用户已有记录结构，只补缺失的必要信息。

## 1. 最小记录与跨聊天恢复

- **归档入口**：分类目录、真实页面链接、工作区标识（工具确实能返回时）、学习目标、默认深度和用户确认的分类例外。
- **整理记录**：按“一个实际资料版本”维护条目。至少包含资料标识、文件名、角色、版本依据、结构覆盖范围、相关知识点链接，以及本批状态。
- **待审核**：只在出现问题时建立。每项包含稳定编号、问题类别、资料版本/定位、目标页面、原有内容、新增观点或拟修改片段、建议选项、审核基线和状态。

初始化前先检索和读取记录页，确认归属同一入口与当前工作区，防止每个聊天重新创建一套记录。已有多个同名记录页时按父页面与内容定位，不能直接新建第三份。

原始附件可能在新聊天中不可访问。记录能恢复进度，但不能恢复已失去访问权的原文；需要原件才能继续的部分，只向用户索取相应文件或范围。没有原件时仍可列出哪些已完成、哪些等待补充。

## 2. 重复上传、改名和版本

将来源身份、文件名与知识点身份分开判断：

| 可核对的证据 | 处理 |
|---|---|
| 原始文件字节的 SHA-256 与已有记录相同 | 同一文件版本，即使改名也先复用记录；未完成时续接，已核对完成时跳过重复导入 |
| 文件名相同但字节指纹或内容不同 | 视为潜在修订，不自动跳过；比较来源说明和内容，保留旧版本记录 |
| 文件字节不同，但对应同一个知识点 | 保留独立来源版本，在同一 canonical 页面比较和融合 |
| 无法取得文件字节或可靠指纹 | 标为“版本未核验”，基于可读内容与现有来源核对；不得伪造哈希或仅凭同名认定重复 |

仅在能访问真实文件字节且已有能力可计算时使用 SHA-256，不为计算指纹安装项目、索取 API key 或假定有固定本地路径。PDF 转换、OCR 或提取文本的指纹必须标明对应衍生物，不能冒充原始文件指纹。

同一指纹不等于整理已完成。检查覆盖范围、未读项与写入状态后再决定跳过。不同资料的相似定义也不构成自动合并概念的充分证据。

用户明确改变学习目标/深度或要求重新整理时，即使原始资料未变，也要执行本次新请求；复用已有证据和来源记录，不将“重复资料”误判为“无需响应新要求”。

## 3. 长文、图表与覆盖范围

先检查可验证的总结构：PDF 实际页数、幻灯片数量、Word 章节/段落/表格。无法验证总量时标为“总范围未核实”，不得报告 100% 完成。

按自然章节或能完整处理的页段分批，不设与文件实际结构无关的固定批次。覆盖记录区分：

- **已提取**：已经取得文字，不代表图表或语义核对完成。
- **已整理并核对写入**：原文与拟保存结论已对照，目标页回读一致。
- **未读/待补充**：尚未处理，或扫描件、公式、图表无法可靠读取。
- **待审核**：原文可读但知识归属或结论存在争议。

每批写完就更新“已完成范围、下一批范围、相关页面 ID”，不用等到整份文件结束。不能用“第 1–20 页已抽字”掩盖第 8 页关键公式未读；单独保留这一缺口。

只有已声明范围全部核对完成、没有未读关键内容、待审核/待分类项已处理、写入已确认时，才可报告该范围全部完成。只整理用户指定的部分时，明确说是该部分完成，不外推到整份资料。

## 4. 自动内容与个人修改

新页分成自动讲解、自动来源记录和个人笔记区域。生成内容首次写入并回读后，保存“目标页面 ID、自动区域边界、同一提取规则下的内容指纹”。若能可靠计算，使用回读文本的 SHA-256；不直接对计划中的 Markdown 求值后当成远端基线。

以后写入前重新读取相同区域：

- 指纹与上次确认一致，且拟增加内容是确定性更新：只修改必要片段。
- 指纹不同：可能是人工编辑或并发变化，保留现文，将原有/拟改内容和当前基线送审。
- 旧页面没有基线、边界不清或工具无法可靠比较：不自动覆盖。可增加独立、明确标记的来源/建议区域；改变已有结论仍需审核。

用户在自动区内的手动修改同样要保护。仅有“自动整理”标题并不意味着助手有权覆盖区内任意内容。不要写入或清空“我的笔记”、掌握度、复习日期和其他个人属性。

摘要或哈希无法消除读取和写入之间的竞争。若发现内容变更、工具前置条件失败或写后回读不一致，停止该项并记录冲突，不重复覆盖试图强行成功。

## 5. 待审核清单与决定

审核状态采用“待决定 → 用户已决定/待应用 → 已应用并核对”，拒绝项保留决定和理由；写入失败不把它标为已完成。分类不明与概念定义矛盾分开记录。

用户可以用条目编号、明确的标题或链接作决定。用户说“全部同意”仅对应刚展示且范围明确的那批建议，不扩展到其他未展示事项；范围不清时只澄清这部分，其他任务继续。

应用前重新读目标页面和相关来源，比较审核时保存的受影响内容基线。若目标或拟修改范围已变，旧决定不能用于覆盖新内容，应展示最新差异再审核。用户批准的是具体建议，不是无限授权重写整个知识点页。

跨聊天继续时从 Notion 读取未完成项；不要把“上一聊天口头决定”当作已成功写入的证据，也不将尚未核对的结果称为成功。

## 6. 写入中断与恢复

在“整理记录”内为即将创建的目标或拟更新的具体区域保留一条操作记录：来源版本、目标父级/页面、知识点、拟变更摘要、操作标识、状态。操作标识必须先存好且能回读，不能每次重试都产生一个新标识。

业务写入前标为“准备写入”；成功回读目标后保存真实页面 ID、覆盖范围及自动区域新基线，标为“已核对”。创建记录要能在新页面的自动来源区域关联到对应操作记录，便于无返回 ID 时查找。

结果不确定时：

1. 有返回页面 ID，先读取该页；异步操作先按工具规定查任务状态，再依赖其结果。
2. 没有页面 ID，在已确定父级下按知识点、操作关联和来源版本检索并读取候选。
3. 唯一结果与原操作内容一致，核对父级后恢复记录，不重复创建；内容部分写入时仅处理可确认缺失的部分。
4. 没有结果或结果不唯一，不代表写入失败。同一未决操作最多两次只读复核，仍无法确认就标记“结果不确定”，暂停该项并告知用户。不得删除记录或换标识来绕过。

只有用户在核对实际 Notion 结果后明确授权重试，或可确定请求在执行前被拒绝且原因已修正，才重新发起对应变更；不要自动重复可能已经生效的创建请求。

记录页自身回写失败时，保留已确认的业务结果，不重新执行业务写入。交付真实页面链接和简短恢复摘要，说明进度记录尚未持久化，不能承诺下一聊天一定能自动续接。连接或权限错误时保留草稿，不在另一个工作区新建替代空间绕过。

## 7. 学习偏好和验收边界

在归档入口保存用户明确表达的学习目标、默认深度、希望使用的例子类型及适用范围。新用户默认理解与应用；本次局部反馈不一定适用于所有课程，保存时保留范围。不凭资料难度或模型印象记录“已掌握”。

技能规则和格式检查只能验证说明是否完整，不能证明运行时可靠性。实际验证应使用用户授权的资料和目标，至少观察重复导入、长文部分未读、个人修改保护、跨聊天审核与一次中断恢复的结果；未经真实调用与回读验证，不声称这些场景已经通过。
